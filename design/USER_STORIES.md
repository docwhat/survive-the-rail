# User Stories

> Who uses it? What tasks are users expecting to accomplish?

## As a Player

### Track Laying (Pre-Round)
- I want to lay track segments before a round starts, so I can define the train's path.
- I want to see the cost of laying track, so I know if I can afford it.
- I want to undo my last track placement, so I can correct mistakes.

### Train Driving (In-Round)
- I want to control the train's throttle and brakes, so I can manage speed.
- I want the train to have momentum and acceleration, so it feels like a real train.
- I want to see the train's current speed, so I know how fast I'm going.

### Combat
- I want my train cars to auto-fire at enemies, so I don't have to aim manually.
- I want enemies to spawn and approach, so there's a reason to keep firing.
- I want obstacles on the track that I can destroy or must avoid.
- I want special enemies that drop chests with rewards.

### Upgrades
- I want to collect XP/money from kills, so I can progress.
- I want a choice of upgrades when I earn enough, so I can customize my train.
- I want upgrades that improve existing cars, add new cars, or extend my track capacity.
- I want chest rewards to be pre-selected (not random) for special enemies.

### Save & Continue
- I want the game to save my full state when I quit, so I can continue later.
- I want to resume from where I left off, so I don't lose progress.
- I want settings split between machine-specific (resolution, volume) and universal (language, difficulty).

### Game Over
- I want to die when enemies overwhelm the train, so there's stakes.
- I want to derail if I hit an obstacle I couldn't destroy in time.
- I want to restart or load a save after dying.

### Meta
- I want to see the beginnings of a story through text, so the game has narrative context.
- I want text to be translation-ready, so others can localize it later.

## As a Friend/Family Member (Polish Pass)
- I want to play the game and give feedback, so the creator can improve it.
- I want the game to be stable and not crash, so the feedback is about design not bugs.

## As the Developer
- I want clean, SOLID code, so I can iterate quickly with ADHD-friendly workflows.
- I want GUT tests for game rules, so I can refactor with confidence.
- I want minimal manual testing, so I don't get burned out repeating checks.
